# Upgrading v4.x → v5.0

## Breaking change: HTTP long-poll is now the default

Workers now receive work through HTTP long-polling instead of the deprecated MQTT transport. The module exports:

```sh
SPACELIFT_WORKER_COMMS_PROTOCOL=poll
SPACELIFT_WORKER_COMMS_URL=<worker_comms_url>
```

The change takes effect when a VMSS instance is created with the startup script generated by v5.0. Existing instances switch transports when they are replaced.

## Action required

Before upgrading:

1. Allow workers to make outbound HTTPS connections on port 443 to their Spacelift server. Check Network Security Groups, Azure Firewall, and any forced-tunnel routes on the worker subnet.
2. Set `worker_comms_url`. It is required whenever `worker_comms_protocol` is `poll`, and the plan fails without it:
   - EU SaaS: `https://app.spacelift.io`
   - US SaaS: `https://app.us.spacelift.io`
   - Self-hosted and FedRAMP: the base URL provided for your environment
3. Remove MQTT egress rules (port 8883) only after all workers have been replaced and are successfully using long-polling.

If you cannot migrate immediately, retain MQTT temporarily:

```hcl
worker_comms_protocol = "mqtt"
```

MQTT worker communication is scheduled to be retired at the end of 2026, so the opt-out is intended only as a migration fallback.

User-provided `configuration` is applied after these module defaults and can still override the exported values, but using `worker_comms_protocol` and `worker_comms_url` is recommended.
